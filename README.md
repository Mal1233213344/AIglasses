# 儿童 AI 英语眼镜项目开发路线图

## 1. 当前结论

这份《儿童AI英语眼镜家长端APP 全套开发交付文档（最终无歧义版）》已经足够作为产品范围和验收基线，但还不能直接支撑全部研发同时开工。

原因很简单：

- 产品需求已经明确到页面、文案、异常兜底、版本差异。
- 真正决定研发速度的“接口契约”还没有细化到字段、协议、状态机、错误码层面。
- 尤其是 BLE、WiFi AP 直连、实时图传、语音对讲、OTA、照片同步，这些都是硬件联调型功能，必须先冻结协议。

文档中的上线截止时间是 **2026-04-22**。按当前日期 **2026-03-26** 计算，距离目标上线还有 **27 天**，必须采用“先主链路、后增强功能”的推进方式。

## 2. 项目范围拆解

整个项目不是一个单独的 APP，而是 4 个需要并行推进的子系统：

1. 家长端移动 APP
2. 后端服务
3. Web 管理后台
4. 眼镜硬件固件对接层

建议把需求拆成以下 8 个研发域：

1. 账号与设备绑定
2. 设备管控中心
3. 学习数据中心
4. 内容同步中心
5. 个人中心
6. 硬件通信能力层
7. 后台管理系统
8. 测试与合规上架

## 3. 版本矩阵

### 标准版

- 设备绑定
- 基础设备状态
- 音量管控
- 时长管控
- OTA 升级
- 低电量提醒
- 学习数据统计
- 词库/音频内容同步
- 个人中心

### Pro 版

在标准版基础上新增：

- AI 纠音开关
- 实景识别开关
- 蓝牙音频开关
- 拍照记录
- 语音对讲
- 定时护眼
- 远程关机/重启
- 实时图传

### Max 版

- 与 Pro 版功能一致
- 后续可以只在内容容量、性能参数、策略配置上做增强，不建议单独做一套代码逻辑

## 4. 技术方案建议

### 4.1 移动端

默认推荐：

- **Flutter** 负责双端 UI、页面状态管理、业务逻辑
- **原生插件层** 负责 BLE、WiFi/AP、UDP 图传、OPUS 对讲、厂商推送、系统权限

推荐原因：

- 文档要求 Android 8.0+、iOS 12.0+ 双端同步交付，Flutter 能显著减少页面和业务代码重复。
- 硬件能力又比较重，不能纯靠跨平台层硬做，最好把复杂通信能力沉到 Android/iOS 原生插件里。
- 这样既能保证交付速度，也能保留硬件联调时的可控性。

移动端建议模块划分：

1. `app_shell`：启动、路由、主题、日志、全局异常
2. `auth`：验证码登录、协议确认、注销
3. `device`：绑定、扫描、设备状态、设备切换
4. `control`：管控指令、离线指令队列、OTA
5. `learning`：学习数据、生词本、报告、打卡
6. `content`：词库、音频、缓存、下载
7. `album`：照片同步、下载、删除
8. `rtc_or_stream`：图传、对讲
9. `profile`：孩子信息、帮助、客服、设置

### 4.2 后端

默认推荐：

- **NestJS**
- **PostgreSQL**
- **Redis**
- **MinIO / 对象存储**
- **OpenAPI**

原因：

- 后台管理、设备管理、内容管理、审计日志、灰度升级、报表导出这类需求，NestJS + PostgreSQL 足够支撑，而且开发效率高。
- Redis 可以做验证码、会话、任务状态、重试队列、离线指令缓存。
- 固件包、内容包、日志、照片元数据适合对象存储。

后端建议拆分为这些服务模块：

1. 用户与认证
2. 设备与绑定关系
3. 设备指令中心
4. 学习数据同步
5. 内容管理与版本分发
6. OTA 固件管理
7. 反馈与日志上传
8. 报表与导出
9. 审计与权限

### 4.3 Web 管理后台

默认推荐：

- **Vue 3**
- **Vite**
- **Element Plus**

后台重点不是炫技，而是高可用、好配置、易审计。优先把这些页面做好：

1. 登录与权限管理
2. 内容管理
3. 设备列表与设备监控
4. 固件升级管理
5. 用户管理
6. 工单与日志
7. 系统配置中心
8. 数据报表

## 5. 研发优先级

必须先做的主链路：

1. 登录与协议同意
2. 定位/蓝牙权限申请
3. 型号选择与设备绑定
4. 首页设备状态
5. 基础设备管控
6. OTA 升级
7. 学习数据同步
8. 内容同步
9. 个人中心基础能力
10. 后台内容/设备/用户三大模块

第二优先级：

1. 照片同步
2. 学习报告
3. 学习打卡
4. 厂商推送
5. 帮助中心与反馈

高风险增强功能，必须独立验证：

1. 实时图传
2. 语音对讲
3. WiFi AP 直连稳定性
4. iOS 热点切换体验
5. OTA 回滚

## 9. 当前最关键的判断

这不是一个“普通家长端 APP”项目，真正的难点在于：

- 硬件协议定义是否完整
- 实时图传和语音对讲是否能稳定跑通
- iOS/Android 对 BLE、WiFi 热点、后台切换的系统限制是否提前验证
- 标准版与 Pro/Max 的差异是否做成统一配置，而不是写成三套逻辑
