## 真机联调目标

把三端在同一局域网内跑通：

- 后端（NestJS）在电脑上启动，手机与眼镜都能访问到
- 家长端 App（Flutter）在真机上运行，能登录、绑定、同步学习/相册、发起图传/对讲
- 眼镜端（设备侧）能带上 x-device-token 调用 device/v1 接口，上报学习、照片、OTA 进度

---

## 0. 环境前置

- 电脑与手机在同一个 WiFi（建议 2.4G，很多设备只支持 2.4G）
- 电脑允许入站端口：
  - 3000（api-server）
  - 3001（admin-web，可选）
- 已安装：
  - Node.js + npm
  - Flutter SDK（Android Studio 或 VSCode 插件可选）
  - Android 真机打开「开发者选项」与「USB 调试」（若要用 USB 跑）

---

## 1. 启动后端（NestJS）

在 `services/api-server`：

```powershell
cd "d:\AI Glasses\services\api-server"
npm install
npm run seed:admin
npm run start:dev
```

确认后端监听在局域网：

- 默认地址：`http://0.0.0.0:3000/api`
- 电脑本机访问：`http://localhost:3000/api`

你可以在手机浏览器里测试（把 `<电脑IP>` 换成你的电脑局域网 IP）：

```
http://<电脑IP>:3000/api/app/v1/health
```

如果没有 health 接口，用任意存在的 GET 接口也行，比如：

```
http://<电脑IP>:3000/api/admin/v1/dashboard/stats
```

---

## 2. 获取电脑的局域网 IP（手机要用）

在 PowerShell 执行：

```powershell
ipconfig
```

找到「无线局域网适配器 WLAN」下的 IPv4，比如 `192.168.1.23`。

后续真机 App 的后端地址就用：

```
http://192.168.1.23:3000/api
```

## 3. 真机运行家长端 App（Flutter）

### 3.1 USB 方式（推荐）

```powershell
cd "d:\AI Glasses\services\mobile_app"
flutter devices
flutter run
```

### 3.2 App 内设置后端地址

打开 App：

- 进入「我的」->「开发者选项」->「后端连接设置」
- 填写：`http://<电脑IP>:3000/api`

保存后回到首页刷新（或重进 App）。

### 3.3 验证关键链路

- 登录：手机号 + 验证码（你当前实现里常用 `13800138000/123456`）
- 绑定设备：走 `app/v1/devices/bind`
- 学习：走 `app/v1/learning/summary|words|practices`
- 相册：走 `app/v1/album/photos`
- 学习报告（AI 寄语）：走 `POST app/v1/learning/reports`

## 5. 眼镜端联调（设备侧接口）

设备侧请求统一走：

- Base：`http://<电脑IP>:3000/api`
- Header：`x-device-token: <deviceToken>`

关键接口（你当前项目里已经存在/常用）：

- 上报设备状态：`POST /device/v1/status-reports`
- 学习数据同步：`POST /device/v1/learning-sync`
- 照片同步：`POST /device/v1/photos/sync`
- OTA 进度上报：`POST /device/v1/ota/tasks/:taskId/progress`

### 5.1 用电脑先模拟设备（推荐）

你已经有脚本可以直接跑：

- [test_photo_sync.ps1](file:///d:/AI%20Glasses/test_photo_sync.ps1)
- [test_learning_sync_v2.ps1](file:///d:/AI%20Glasses/test_learning_sync_v2.ps1)
- [test_ota_flow.ps1](file:///d:/AI%20Glasses/test_ota_flow.ps1)

把脚本里的 `$base` 改为你的局域网 IP（或保持 localhost 在电脑跑），把 `$deviceId/$deviceToken` 固定下来，然后：

```powershell
powershell -ExecutionPolicy Bypass -File "d:\AI Glasses\test_photo_sync.ps1"
```

当脚本跑通后，再把同样的请求逻辑搬到真机眼镜侧，会省掉大量排查成本。

## 6. 常见坑位排查

### 6.1 手机访问不到后端

- 先确认手机能 ping 到电脑（同一 WiFi）
- Windows 防火墙放行 3000 端口入站
- 后端必须监听 `0.0.0.0`（当前项目已配置）

### 6.2 Android 真机访问 localhost

真机不能用 `localhost/127.0.0.1/10.0.2.2`（那是模拟器专用）。

真机必须用：`http://<电脑IP>:3000/api`

### 6.3 WebRTC 图传/对讲

当前可以用后端 mock 信令做 UI 验证，但真机图传通常还需要：

- STUN/TURN 服务（跨网、弱网必须）
- 设备端真实推流（摄像头/麦克风采集 + WebRTC）

如果你告诉我眼镜端的系统与推流栈（Android/Linux/ESP32 + 哪个 WebRTC 实现），我会按你的栈给到“逐步打点”的联调方式。

## 7. 到“真机联调阶段”的判断标准

满足以下条件就可以开始真机联调：

- 手机能访问 `http://<电脑IP>:3000/api/...` 任意接口
- App 中已设置 apiBaseUrlOverride 指向电脑 IP
- 登录/绑定/学习/相册至少有一条链路能在真机上跑通

你准备开始时，直接把：

- 电脑 IP
- 手机型号（Android/iOS）
- 眼镜端系统（Android/Linux/其他）与联网方式（WiFi/4G/热点）
